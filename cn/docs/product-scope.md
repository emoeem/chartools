# 国内版产品范围与验收基线

本文把通用产品规划清单改写为适用于 `cn/` 国内版 Android 聊天助手的基线。它描述现有产品应保持的目标和边界，不代表本文提到的每个规划缺口都已实现。实际平台支持和操作细节以[项目总览](../../.github/README.md)为准；隐私与数据处理以[隐私政策](../PRIVACY.md)为准；构建及已有真机验收以[验收标准](acceptance.md)为准。

## 1. 产品目标与使用场景

### 目标

在用户自己正在查看、且当前版本支持的聊天界面中，读取屏幕可见的对话，分析对话并给出候选回复，帮助用户理解上下文和组织表达。

### 主要场景

1. 用户打开受支持的聊天会话，应用在本机读取界面文字；界面不提供可读文字时，对支持的路径使用本机 OCR。
2. 用户启用自动分析，或在悬浮卡上主动触发分析。
3. 应用将本轮所需的聊天文字及用户启用的背景信息发到用户配置的模型接口，展示判断和候选回复。
4. 用户自行选择复制、填入或忽略候选；是否发送始终由用户决定。

### 不可突破的产品边界

- 不自动发送消息，不操作转账、红包或收款。
- 只读取用户本人有权查看、当前屏幕可见且适配的内容；不读取聊天数据库或隐藏界面内容。
- OCR 图片在本机处理，不上传截图。
- 微信语音消息只识别微信界面已显示的“转文字”结果；用户需先在微信中操作转文字。助手不直接读取或上传语音音频。
- 聊天文字只发往用户配置的模型接口；不得加入作者自营的聊天内容收集或遥测链路。

## 2. 页面框架与导航

当前国内版是单应用内的设置式导航，不是多标签页或任务管理器：

```text
启动器
└─ 首页（MainActivity）
   ├─ 系统权限设置（Android 系统页面）
   ├─ 设置（SettingsActivity）
   │  └─ 知识库与联系人（KnowledgeActivity）
   │     └─ 文档导入（DocImportActivity）
   └─ 聊天应用中的悬浮卡（AccessibilityService）
      └─ 设置快捷入口
```

知识库页内部有“笔记 / 联系人 / 技能”三个页签。悬浮卡覆盖在聊天应用之上，是主要的分析结果入口，不是单独的首页。

项目没有“今日计划”或每日任务模块。除非未来需求证明它能直接改善聊天分析的核心场景，否则不加入导航和第一版范围。

## 3. 首页内容结构

首页（`MainActivity`）的当前职责是安装后的权限引导和运行状态检查，不承担聊天内容浏览或每日任务管理。内容按以下顺序组织：

1. 产品用途与发送由用户决定的提示。
2. 就绪状态卡：区分无障碍权限、无障碍服务实际运行、悬浮窗权限和必要密钥状态。
3. 单一分步引导：按顺序只突出当前缺少的必需项（无障碍、悬浮窗、判断接口 API Key）；无障碍服务使用清楚易辨认的名称，返回首页后自动刷新并进入下一步。
4. 隐私与第三方聊天平台使用风险提示。
5. 设置入口和总开关。
6. 国产手机省电设置与 root 增强收纳在默认折叠的兼容性设置中；无 root 时核心路径仍可使用。

验收首页时应检查权限实际状态和服务存活状态，不可只根据 Android 设置中的开关显示“已就绪”。首次配置不应同时展示多张必做卡片；每一步返回后应自动识别状态并推进。Android 不允许普通应用静默开启无障碍；用户仍需在系统页开启并确认，但页面应明确告知要找的服务名称。

## 4. 模块用途、必要数据和操作

| 模块 | 用途 | 第一版必要数据 | 用户操作 / 输出 |
|---|---|---|---|
| 首页与权限引导 | 让用户完成首次配置并判断是否可用 | 无障碍授权及运行状态、悬浮窗权限、必要接口密钥、总开关 | 查看缺项、跳转系统设置、一键修复可用项、启停服务 |
| 聊天采集与适配器 | 把当前支持的聊天窗口转换为会话标题和可见消息 | 应用包名、窗口/会话身份、消息文本及我方/对方方向；不持久化屏幕截图 | 自动识别支持的会话；树不可读时走对应 OCR；对未适配应用仅提供明确标注限制的手动识别 |
| 判断与回复 | 分析意图、风险及回复时机，生成并排序候选 | 当前会话快照、必要的接口配置、用户启用的上下文 | 自动或手动分析；显示判断和候选；错误应可读且不得泄漏密钥 |
| 悬浮卡 | 在聊天上下文中呈现结果并提供安全操作 | 当前结果、候选、强度档位和必要会话状态 | 查看、复制、填入、换一组、调整档位；填入不得触发发送 |
| 知识库与联系人 | 为分析提供用户维护的事实、联系人背景和表达参考 | 笔记、姓名/别名/关系/备注、技能包；按设置可选聊天历史 | 新建、编辑、导入、启用/停用、删除；查看命中计数并清空知识库与历史 |
| 接口设置 | 由用户指定判断、回复和视觉服务 | 服务地址、模型、密钥和协议/预设 | 编辑、选择预设、单路测试；回复/视觉配置留空时按现有规则继承，不应意外覆盖既有密钥 |
| 可选增强 | 为已验证的设备或平台提供非必需能力 | 显式开关及每应用配置 | 可关闭并回落基础采集路径；不得成为普通设备使用核心功能的前置条件 |

## 5. 首页、分析流程与模块关系

核心工作流为：

```text
首页检查就绪
  → 用户进入受支持的聊天会话
  → 无障碍适配器 / 本机 OCR 读取可见消息
  → 会话身份与新消息门禁判断是否需要分析
  → 可选地匹配联系人、历史、笔记和技能
  → 用户配置的判断/回复接口生成并排序候选
  → 悬浮卡展示结果
  → 用户复制、填入或忽略；发送由用户手动完成
```

首页只负责权限和开关；设置页负责配置；知识库页负责用户数据；悬浮卡负责当前会话的即时交互。模块之间通过会话快照和用户明确启用的上下文衔接。没有“今日计划”数据流，也不应为凑齐模板添加该功能。

## 6. 本地数据、备份与恢复

### 当前数据位置与生命周期

| 数据 | 当前存储 | 当前行为 |
|---|---|---|
| 接口密钥、地址、模型和用户设置 | App 私有 SharedPreferences；密钥使用 Android Keystore 保护 | 更新或清除设置时修改；卸载应用会删除 |
| 笔记、联系人、聊天历史及其派生上下文文件 | `filesDir/kb/`，JSON 文件；历史按联系人分文件 | 聊天历史默认关闭，开启后按现有上限保留；设置页可清空知识库与历史 |
| 用户导入的技能 | `filesDir/skills/` | 在知识库页查看、启用、停用或删除 |
| 屏幕截图与 OCR 中间图像 | 内存中的处理流程 | 不作为用户文件保存，不上传；处理后释放 |

### 备份与恢复状态

当前没有应用内完整备份/恢复功能；不能承诺卸载、换机或系统迁移后用户数据一定可恢复。清空知识库与历史不是备份功能，密钥也不能因为“备份方便”而默认导出。

后续若将备份纳入发布范围，需先明确导出数据类别、加密方式、用户确认、文件格式兼容策略和失败恢复流程。最低验收要求为：导出内容可由用户检查；默认排除 API 密钥；恢复前显示将导入的数据类别并要求确认；无效/损坏文件不得造成部分覆盖或丢失现有数据；导入成功后可核对数据条数。完成这些设计和实现之前，备份恢复应标记为未提供，而不是已满足。

## 7. 当前维护基线必须保持的功能

本项目已有多个版本，因此此处的“第一版”指产品核心能力基线，不指重新从零开发的 v1.0，也不自动构成某个未发布版本的承诺。

- 首页能指出权限缺项，并区分权限已开但服务未运行的状态。
- 用户可配置必要的判断接口，并独立配置或继承回复/视觉接口；接口支持连通测试。
- 对当前平台支持表中标明支持的聊天应用读取可见会话；未适配路径必须明确标为手动/有限能力。
- 自动分析和手动分析遵守当前会话隔离与新消息判定；切换会话不得复用上一会话的分析上下文。
- 展示判断和多个排序候选；用户可复制或填入，任何路径都不得自动发送。
- 提供用户管理笔记、联系人和技能的能力；聊天历史为可选且默认关闭。
- 提供本机清除知识库与历史的能力，并在文档中说明 API 密钥、历史和其它设置的存储及删除边界。
- 错误需对用户可理解；密钥和聊天正文不得进入日志。
- 可选 root/注入增强不能成为无障碍基础功能的必要条件。

## 8. 当前版本暂不纳入的功能

除非单独评估、明确排期并补上隐私与验收要求，以下不属于核心基线：

- “今日计划”、日历、提醒、连续打卡或每日任务面板。
- 自动发送、自动点击发送键、代替用户操作聊天账号或处理钱款。
- 读取聊天数据库、后台隐形抓取、读取用户未打开的对话。
- 未验证平台的自动采集承诺；平台支持范围以总览中的实测状态为准。
- 云端账号、同步、作者自营中转/内容收集服务。
- 自动把用户数据或密钥上传到云端的备份；当前也没有应用内完整备份恢复。
- 语义检索以外的新能力，除非有独立需求和效果验收；不能把规划中的能力当作已有功能宣传。

## 9. 可执行验收标准

每次涉及产品行为的改动至少按相关用例检查；完整构建、测试与既有真机标准见[公共验收标准](acceptance.md)及[国内版总览](../../.github/README.md)。

| 编号 | 检查步骤 | 通过条件 |
|---|---|---|
| A | 全新安装后只授予部分权限 | 首页准确指出缺少项，不显示虚假的“已就绪”；无障碍开关开但服务不存活时明确提示 |
| B | 配置必要接口后打开已支持聊天会话并触发分析 | 读取当前可见会话并展示判断及候选；未配置密钥或网络失败时显示可理解错误、不崩溃 |
| C | 使用自动分析、手动分析及“换一组” | 自动分析仅在规则允许时触发；手动入口可用；换一组复用当前会话分析上下文 |
| D | 从会话 A 切换到会话 B，再返回 A | B 不显示或使用 A 的快照、候选、判断、去重门禁或知识上下文；切回 A 按新会话流程重新判定 |
| E | 在候选上分别点击复制和填入 | 文本进入剪贴板或输入框；应用不点击发送，不因回退粘贴而发送 |
| F | 新建笔记和联系人，启用聊天历史后分析，再清空知识库与历史 | 命中计数符合实际；历史未启用时不新增；清空后 `kb` 数据归零，接口密钥与一般设置仍保留 |
| G | 检查截图/OCR路径 | OCR 在本机完成；截图不保存、不上传；失败时给出原因或可理解提示 |
| H | 检查日志和断网行为 | 日志中无密钥和聊天正文；断网显示错误且应用不崩溃 |
| I | 试图按产品文档寻找备份/恢复入口 | 当前版本应明确说明该能力未提供，不得声称数据可完整迁移或恢复 |
| J | 执行国内版构建、单元测试、Lint | Gradle 任务成功；APK 产物存在；新增会话状态逻辑由单测覆盖 |

## 10. 文档维护规则

- 项目总览负责面向用户的现有功能与平台状态；隐私政策负责数据流、存储和删除事实；本文件负责产品边界、模块关系和验收基线。
- 规划中的能力必须标为“未实现/规划”，不能写成已交付。
- 新增页面或模块时，先补充本文件的用途、数据、用户操作、数据生命周期和验收步骤，再实现功能。
- 修改核心数据边界、发送行为或权限行为时，必须同步更新隐私政策并增加回归验收。

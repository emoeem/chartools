# 人设库：让人设变成用户可以自己攒的数据

日期：2026-10-22 ｜ 范围：`cn/`（com.jev.probe 2.0 / code 10）｜ 结论：**已实现、单测与真机双验，代码在工作区未提交**

---

## 1. 用户要的是什么

> 「人设是一个可以用户自己的配置的功能，不是硬编码的，比如用户可以通过自己的训练或者对应的 skill 和知识库来设定一个人设，比如我销售的时候需要一个销售的说话风格。」

翻回代码，原状确实是硬编码：

| 位置 | 原状 |
|---|---|
| `core/kb/PersonaPresets.kt` | `ALL` 里三张卡：网调·我是主 / 网调·我是奴 / 日常 |
| `SettingsActivity` | 三个按钮，点一下把整段文本塞进一个 EditText，之后只剩文本 |
| `KnowledgeActivity` | 联系人专用人设用的是**同一批**三个模板按钮 |

也就是说：模板是代码的一部分，用户没法新增；写出来的自由文本一旦离开设置页就没有名字、不能复用、换机器就丢。

## 2. 做成了什么

### 2.1 数据层：`PersonaStore`

`filesDir/kb/personas.json`，`{"version":1,"items":[{id,name,body,updatedAt,builtin}]}`。

| 能力 | 语义 |
|---|---|
| `list()` | 文件不存在 → 用 `PersonaPresets` 播种（四张）；**逐条删光不会再长回来**（文件还在，items 空） |
| `save(name, body, id?)` | 新建 / 原地更新；`body` 全空则拒绝（返回 null），不留空壳 |
| `delete(id)` / `duplicate(id)` | 删除；复制按 `名字 副本`、`名字 副本 2` 递增，不撞名 |
| `importJson(text)` | 认整段导出 JSON、`{"items":[…]}`、单个对象，以及**一整张纯文本人设卡**（第一行当名字） |
| `exportJson()` | 全量 JSON（界面侧复制到剪贴板，不申请存储权限） |
| `restoreBuiltins()` | 只补回缺的内置条目 |
| `activeOf(style)` | 用原文比对反推「现在生效的是哪一条」；自由文本返回 null |

三条硬约定（都有单测钉着）：

1. **导入永不覆盖同名** —— 同名不同文另存 `名字(导入)`；内容完全相同时跳过。
2. **文件坏了先备份再放行** —— 写 `kb/personas.corrupt-<时间戳>`，`lastProblem` 上界面；不静默清空用户的库。
3. **当前生效的人设不存 id** —— 见 §4。

### 2.2 界面层：设置页人设区

```
人设决定回复的语气、称呼和分寸。下面是一个可以自己攒的库：写一份「销售·跟单」，
点「用」就切过去，回复的口气立刻跟着变。
当前生效：「网调·我是主」
┌──────────────────────────────────────────────┐
│ 网调·我是主                 生效中            │
│ 主题「网调」·称呼「…」·硬边界 2 条·示例 3 句  │
│ [用] [改] [⋯]                                 │
└──────────────────────────────────────────────┘
  …（网调·我是奴 / 日常 / 销售·跟单）
[新建] [导入] [导出] [恢复模板]
人设原文（保存时写进设置，也可以直接改）
[ 称呼：… 关系：… 语气：… ]        ← 仍是原来那个框
已识别：称呼「…」·关系·主题「网调」·硬边界 家人、前任·示例 3 句
知识库：主题「网调」命中 674 条，只从这 674 条里挑…
```

- **「用」立刻生效**：`personaDraft.setText(body)` + `prefs.style = body`，不等「保存全部设置」。套用是个明确动作，按了就该变；而且输入框同时被改写成同一段文本，所以随后按「保存」写下去的还是一致的。
- **新建/编辑对话框**：名字 + 正文（预填键骨架）+ 实时识别回显 + 两个帮手：
  - 「插入键骨架」：把 `称呼／关系／语气／主题／情境／硬边界／示例／我：` 补进去；
  - 「收进语气示例」：读知识库里 `NOTE_TYPE_STYLE_SAMPLE` 的笔记，抄成 `我：…` 行塞进示例段。
- **⋯ 菜单**：重命名 / 复制一份 / 导出这段正文（复制）/ 删除（带二次确认，并说明「已套用到设置里的文本不受影响」）。
- **每行摘要**（`PersonaStatus.short`）：先说清楚**这条套用之后会不会真的生效** —— 认不出键的卡在列表里看起来完全正常，套用后回复照旧，那是最容易让人放弃的失败。所以自由文本会直接标 `⚠ 没认出键：…主题/硬边界/语域都不生效`。

### 2.3 内置卡：新增「销售·跟单」

```text
称呼：按对方名片上的称呼，姓＋总或姓＋老师
关系：销售和客户，我给方案，他做决定
语气：短句、具体，先给结论再给理由，不催不捧
主题：销售
情境：微信或电话跟单，隔着屏幕
硬边界：稳赚、保证收益          ← 不能承诺收益，逐字进闸门
示例：
我：王总，方案按您上次说的改完了，您看哪天方便过一遍
我：这个折扣我申请不下来，先如实跟您说
我：不急，您先忙，我明天上午再跟您确认
```

`PersonaPresetsTest` 会遍历 `ALL` 逐张校验（键完整、边界是双字词、示例都是「我：」开头），所以新卡自动受约束。

### 2.4 联系人专用人设也接到库里

`KnowledgeActivity.personaPresets()` 原来是三张写死模板，现在读 `PersonaStore.list()`，两列排布、点一下填进联系人的专用人设框；库空时直接指路「先去设置 → 人设与语气建一份」。读盘在线程里做（对话框构造路径不能等 IO）。

### 2.5 清空的语义

`KbStore.clearAll()` 会删掉整个 `kb/` 目录，人设库在里面，所以它会一并消失、下次读重新播种。确认框改成如实说出这件事：

> 将删除 N 条笔记、M 个联系人、K 条聊天历史，以及 **X 份人设（人设库会回到内置模板）**。密钥、白名单等设置不受影响。不可恢复。

## 4. 为什么「当前生效」不存 id

生效的仍然是 `Prefs.style` 那段文本，库只负责「名字 + 原文」。如果库里再存一个 `activeId`：

- 用户在原文框里手改一个字 → id 就过期了，但没有任何事件能可靠触发清理；
- 清理不及时的后果是**界面说生效的是 A、实际发出去的是 B**；
- 这种不一致没有报错可查，只能靠用户发现「回复不对劲」——最贵的一种 bug。

所以判定改成 `activeOf(style)`：原文 trim 后相等才算「生效中」，自由文本显示「未存进库的自由文本」。代价是每次打字都要重画列表（内存操作，可接受），收益是**不存在两份可以互相矛盾的状态**。

## 5. 缺口与后续

1. **导出只到剪贴板**，没有 `.json` 文件导出/分享面板。要跨设备搬运够用（粘贴即可），要备份额外再加 SAF 写文件。
2. **人设不能按联系人/按应用自动切换**：现在是「设置里选一份 + 联系人覆盖一份」。要「QQ 用销售、Telegram 用日常」需要一个新的按包名映射层，属于独立改动。
3. **没有「从对话里学人设」**：用户提的「通过自己的训练」目前落在「知识库语气示例 → 收进卡片」这一层，是手动的。自动抽取语气特征需要模型侧改动，未做。
4. **版本号没动**（仍 2.0 / code 10），git 未提交 —— 按惯例等拍板。
